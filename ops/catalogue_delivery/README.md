# Сборка единой выдачи из сохранённых разборов

Это операторские инструменты текущей полной оцифровки. Они используют существующие приватные `.tmp/full-digitization/staged-best-v1.4.8` и `.tmp/root-tail-review-20261014`; новый PDF сами не извлекают и модели не вызывают. Запускать из корня этого репозитория в проверенном окружении `catalog-to-json` 1.5.24 с PyMuPDF и openpyxl.

Последовательно выполнить `integrate_completed.py`, затем `sync_independent_reviews.py`, затем `build_snapshot.py`. Для сборки: один процесс, RAM 3 GiB, CPU-время 600 секунд, аварийный wall-limit 900 секунд, временные данные до 512 MiB. Перед запуском проверить свободные ресурсы; не запускать одновременно несколько сборок.

Интеграция сохраняет прежние авторские выходы и доказательства. Новая авторская ревизия выбирается по времени proof и точному SHA, включая исправление только геометрического evidence. Независимый PASS привязан к исходному PDF, странице, полному изображению и точным байтам другого автора. Настоящие неизвестные значения не удаляются. Исторический флаг `unchanged_native_candidate` не отменяет зарегистрированные авторские corrections. Нативные candidate/review/result не переписываются.

Сборщик предпочитает актуальный independently verified результат старому ручному черновику, сохраняет фактические версии производителей и различает выполнение независимой сверки и успешную приёмку. REVISE также сохраняет проверяющего и причину в JSON и Excel. Проверки архива включают CRC, 980 PageContent, пять повторно открытых Excel, все табличные значения и атрибуцию независимых проверок. Незавершённая приёмка не объявляется полным каталогом.

`build_snapshot.py` записывает собственную версию и SHA исходника внутрь JSON. Он не публикует файлы в GitHub: публикация и проверка скачивания выполняются отдельно. Сырые транскрипты, исходные PDF, секреты и приватные изображения в выдачу не входят.
