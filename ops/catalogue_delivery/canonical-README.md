# Чистое сведение сохранённых каталогов

`canonical_merge.py` читает неизменённые сохранённые наблюдения и решения,
применяет source-bound выборы/уточнения и создаёт **один** набор records.
Это не OCR, новый модельный прогон или доказательство точности всех исходных PDF.
Исходные значения выбираются из наблюдений; допустимые варианты объединяются
только по явно проверенным option_sets. Противоречие одного физического свойства
останавливает сборку. Проверенные противоречия самого PDF получают null и
state=source_conflict; обе альтернативы остаются в отдельном сравнении.

При объединении равных значений сохраняются конкретная модель, деталь,
условие и единица. Пустая область восстанавливается только из сохранённой
same-fact пары; разные явные области не схлопываются по совпадению числа.

Смысловой ключ: каталог, вид факта, модель, параметр, деталь и условие.
Страница служит доказательством, а не искусственным различающим условием.
Подписи чертежей, описание, оглавление, условия испытания и справочный контекст
сохраняются типизированно и не объявляются отдельными предложениями товара.
Реальные многозначные характеристики могут иметь массив исходных значений.
None/пустая строка/прочерк/ноль различаются; совпадение чисел не склеивает модели.

`canonical_export.py --input CATALOGUE.json --output NEW_DIR` создаёт Excel
из records этого же JSON. Длинные значения разбиваются без потерь; исходные
строки не исполняются как формулы. В чистом ZIP только JSON, Excel, README и
manifest. comparison.jsonl/CSV, решения и исходные архивы хранятся отдельно.

Сравнение содержит каждый исходный factID, включая несопоставленные
наблюдения с явным статусом unpaired_source_observation. only_ours_mapped
означает лишь наличие доказанного соответствия с нашей стороны; это не
доказательство пропуска у Олега. different_source_representations_or_values
также не является числом ошибок: там есть различия оформления. Исправленные
выборы и причины вынесены в corrected_selection/reason. Полный журнал
наблюдений и решений нужен для воспроизведения, но не входит в чистый каталог.

`verify_canonical.py` независимо повторно открывает JSON, Excel и ZIP, проверяет
типы и все записи, 980 страниц пяти источников, версии производителей,
неизменённый исходный список42, выбранные поля трёх структурных замен и хеши.
Версия канонического сборщика1.0.0 и фактический git/sourceSHA записаны в metadata;
исторические извлекатели и их версии не заменяются версией сборщика.

Ресурсы: один процесс наоперацию, RAM2GiB для merge,1.5GiB для export/readback,
один CPU напроцесс, без дополнительного swap. Проектный общий бюджет14GiB/2CPU.
Небольшие тесты expected2s/emergency20s; полный retained build expected120s/max1200s,
Excel/readback expected120s/max1200s; вся работа в project .tmp/, не system/tmp.
Новые файлы не перезаписывают предыдущий доставленный ZIP.
