# Architecture

The product is a versioned Agent Plugin 1.0 package: portable extraction/review skills plus local catalog MCP tools and a FastAgent CLI runner. Native Codex/Claude manifests share the same source skill files. Wheel packaging bundles the skills so an installed CLI does not depend on a Git checkout.

FastAgent runs an actual model-powered tool loop. Skills are registered using its native skills API and `{{agentSkills}}`, and loaded on demand. The extractor reads AnyDoc, sees the original page, chooses zooms/rotation, reads the file schema and writes JSON with tools. Its chat response need not be structured JSON. File-tool validation errors are fed back into the same agent loop. Large pages can be written as validated sections and assembled by finalize_page.

AnyDoc supplies PDF text locally. Its pinned Python PDF API exposes Markdown, not the shared document IR. Markdown is a fallible diagnostic intermediary, never the output contract. A simple direct candidate can be reused after visual comparison; complicated or incomplete content is reconstructed by the agent using Vision.

The reviewer has a separate model context and tool process. It first transcribes the original independently into a tool-saved source observation; candidate access is blocked until then. Source observations freeze at candidate disclosure. A deterministic comparison checks physical-column values, states, units, qualifiers, wording and diagram labels. Only then does the reviewer read the candidate and search for further defects. It chooses its own crops and records all defects. Both roles must actually view the page; rotated text also requires a region view. Artifact saves require tool evidence. Reviewer tools cannot modify the candidate. All eleven check categories need evidence, independent source dimensions must match, and any issue/unknown/uncertainty prevents acceptance. This gate cannot guarantee a model's visual judgment is correct.

Schema validation belongs at save_page_json/save_section/finalize_page/save_review. It catches invalid fields, ragged rows, missing cells and contradictory claimed passes. A claimed pass is blocked when independently recorded source facts contradict the candidate; non-pass reports retain all comparator findings even if the model forgets one. It does not force the agent's conversational response into a schema. Repair receives the candidate and reviewer findings, reinspects the source, saves a new candidate and goes through a fresh review.

Tables use named columns and exactly one typed cell per column/row. blank means a real source blank; unknown means unreadable evidence. Units and qualifiers are separate. Symbols and Cyrillic/Latin codes stay literal. Independent tables never inherit data without source evidence. Source typos remain literal in data and are explained separately.

Drafts, reviews, chosen crop images and tools.jsonl are retained privately with source SHA256, page number and selected models. complete_for_selection is separate from catalog_complete. Interrupted runs are not accepted. Bounded workers and a job deadline limit resource use. No background job, global MCP installation or hidden provider fallback is used.

The approach adapts the successful original-page Vision skill in [pdf-markdown-docx](https://github.com/megamen32/pdf-markdown-docx) and the separate extraction/cleanup idea from [pdf_to_docx_ocr_llm](https://github.com/megamen32/pdf_to_docx_ocr_llm). Catalog values are never hand-corrected by the CLI developer.
