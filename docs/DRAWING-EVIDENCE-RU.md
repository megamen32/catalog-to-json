# Исходные линии чертежей и происхождение экспорта

Версия1.4.26 добавляет в native MCP два инструмента. `inspect_drawing_geometry` даёт слова с направлением текста и компактный индекс путей в координатах исходного изображения. `read_drawing_paths` возвращает точные концы линий, контрольные точки кривых, стиль и заливку выбранных устойчивых ID. Большие слова/пути доступны через прежнюю пагинацию, без обрезания сегментов. Индекс по умолчанию показывает штрихи; `path_kind=all/fill` явно включает остальные контуры. Контуры букв могут быть очень сложными, поэтому агенту нужно выбирать небольшую область и нужные ID.

Это исходные данные, а не автоматически определённые названия деталей. Навыки требуют для каждого исполнения и вида связать размер с обоими концами выносок и видимым измеряемым контуром, проверить направления видов и не угадывать материал/функцию. Разбитая на отдельные сплошные сегменты окружность всё равно может выглядеть штрихпунктирной: стиль проверяется на оригинальном увеличении. Для растров остаётся Vision.

В Excel появился лист «Происхождение»: физическая PDF-страница и напечатанный номер, исходный файл и SHA, модели, фактические версии/хэши извлекателя и проверяющего, время последнего вызова каждой роли. Новая версия экспортёра не заменяет версии создавших данные программ. Неподтверждённый производитель обозначается явно. JSON уже хранит раздельные source-bound receipts ролей.

На оригинальных OPN27/39/35 native MCP проверил совпадение выбранных путей с PDF; исходный файл не изменён. Сохранение страницы35 → редактирование её чертежа → финализация сохранило все поля,64 ячейки и текст. Эти проверки подтверждают транспорт и сохранность данных, а не точность модели.

Три новых целевых модельных прогона чертежей — отдельное испытание версии26. До их завершения версия не получает прежние97,69% и не заменяет замороженную связку15→17 в полном бенчмарке или текущие роли массовой оцифровки.97,69% — текущие выбранные инженерные факты одного чернового прогона; чертежи оцениваются отдельно.

Версия1.4.27 добавляет `trace_dimension_candidates`: для числовой подписи показывает до6 ближайших параллельных линий с маленькими залитыми треугольниками у концов. Концы штриха и предполагаемые острия треугольников возвращаются отдельно: штрих может заканчиваться у основания стрелки. Это эвристический список исходных координат, а не распознавание назначения деталей. Пустой список требует Vision/полного индекса; все исходные пути сохраняются. На OPN27 короткий штрих размера45 меньше4 PDF-пунктов, поэтому фильтр длинных линий потерял бы его. На OPN39 конец штриха274 и острие стрелки попадают на разные уровни профиля. Отдельная модельная проверка версии27 не наследует качество26/15.
