## Приёмка

1. Точное взаимно-однозначное соответствие исходных записей и сохранённых преобразованных записей, проверенное обратным восстановлением типов/значений/пустот/null/порядка/header_path/provenance. Исходные файлы и их SHA сохраняются. Перекрывающиеся наблюдения не склеивать молча; они не уникальные SKU.
2. Смысловое соответствие фактов отделено от обратимого формата. При one-to-many/дублях/неоднозначности сохранять соответствия и остатки, не придумывать ложную биекцию и не игнорировать unmatched данные.
3. Полный реестр: эквивалентные данные, разница представления, реальные противоречия, пропуски с каждой стороны, неустановленное соответствие. Для каждого точные указатели к обоим входам и исходнику, реальные значения/единицы/условия/табличные объединения/принадлежность размеров.
4. Для КАЖДОГО спорного факта три независимых verdict (Codex/ZCode/MiniMax) с caseID и входнымиSHA. Сначала независимые суждения по оригиналу; затем только спорные повторы с аргументами. Большинство/мнение одного участника не выдавать за консенсус. Если источник не позволяет установить значение, общий unresolved вместо догадки. Исходные/native результаты не переписывать.
5. Общий merged JSON и Excel, полный отчёт о расхождениях, все три актуальные оценки и происхождение принятого значения, переносимость/распаковка/roundtrip/coverage проверены. Ни partial, ни подготовка runner не завершает поручение.
